# Repo Layout

What the top-level files and folders are for in each type of flowscripter repo. The types and their templates are listed in `scripts/repo-types.json`, and each repo starts from `template-<type>`.

## Folders in Every Repo

| Path | What it holds | Committed |
|---|---|---|
| `src/` | source code | yes |
| `tests/` | unit tests | yes |
| `README.md` | what the repo is and how to use it. It also ships in the npm package. | yes |
| `README/` | longer user and developer docs, where a repo needs them, for example `key-concepts.md`, `development.md` and `implementation-details.md` | yes |
| `design/adr/` | architecture decision records for this repo. Org-wide ones are in `flowscripter/.github/docs/adr/`. | yes |
| `design/changes/NNNN-slug/` | the spec and plan for each change made through the agent workflow. It is history: agents read only the change they are working on. | yes |
| `.claude/CLAUDE.md` | agent context for this repo | yes |
| `.claude/skills/` | repo-specific agent skills, if any | yes |
| `.claude/` (anything else) | local agent settings and plans | no |
| `.github/workflows/` | thin callers of the shared workflows in `flowscripter/.github` (`validate-*-pr`, `release-*`, `check-*-dependencies`, `lint-pr-message`) | yes |
| `.github/CODEOWNERS` | `* @vectronic`, so GitHub requests Nick's review on every PR | yes |
| `LICENSE` | licence | yes |

Specs, plans and ADRs live in `design/`, never in `docs/`. `docs/` is generated, gitignored output, and typedoc empties it on every run.

## Bun Repos

Shared by the bun-library, bun-executable, bun-webapp, bun-rust-library and bun-wasm-rust-library types.

| Path | What it holds | Committed |
|---|---|---|
| `index.ts` | the package entry point. Bun consumers import it directly, through the `bun` export condition. | yes |
| `package.json`, `bun.lock` | the package manifest and lockfile | yes |
| `tsconfig.json` | the type-check configuration | yes |
| `tsconfig.build.json` | the build configuration (`bun run build`, which runs `tsc -p tsconfig.build.json`) | yes |
| `dist/` | build output: `.js` and `.d.ts` files for non-bun consumers. It is published in the npm package (`files`). | no |
| `docs/` | typedoc API docs, generated by the release workflow and published to GitHub Pages | no |
| `coverage/`, `node_modules/`, `out/` | coverage reports, installed packages, scratch output | no |

### Bun Executable

| Path | What it holds | Committed |
|---|---|---|
| `functional_tests/` | Python Behave tests that run the compiled executable. `pip-requirements.txt` lists their dependencies. | yes |
| `functional_tests/executable` | the executable those tests run, compiled with `bun build index.ts --compile` | no |
| `script/install.sh` | the install script for the released binaries | yes |

Releases compile one executable per platform. The release workflow signs them, attaches them to the GitHub release, and updates the Homebrew tap and winget.

### Bun Webapp

| Path | What it holds | Committed |
|---|---|---|
| `html/index.html` | the page that `build.ts` bundles | yes |
| `build.ts` | the bundler script (`bun run build`) | yes |
| `dist/` | the bundled site, which the release workflow publishes to GitHub Pages | no |
| `functional_tests/` | Python Behave tests driven through Firefox and geckodriver | yes |

### Bun + Rust Library (FFI)

| Path | What it holds | Committed |
|---|---|---|
| `Cargo.toml`, `Cargo.lock` | the Rust crate that builds the native library | yes |
| `target/` | Cargo build output | no |

The release workflow builds the native library for each platform and attaches it to the GitHub release, and `package.json`'s `ffiLibBaseUri` points at those downloads.

### Bun + Rust WASM Library

| Path | What it holds | Committed |
|---|---|---|
| `Cargo.toml`, `Cargo.lock` | the Rust crate compiled to WebAssembly | yes |
| `pkg/` | wasm-pack output, copied into `dist/pkg/` by `bun run build` | no |
| `target/` | Cargo build output | no |

## Rust Library

| Path | What it holds | Committed |
|---|---|---|
| `Cargo.toml`, `Cargo.lock` | the crate manifest and lockfile. The release workflow publishes it to crates.io. | yes |
| `target/` | Cargo build output | no |

## Special Repos

- **`.github`:** the shared workflows (`.github/workflows/`) and composite actions (`actions/`), workflow templates (`workflow-templates/`), the org issue forms (`.github/ISSUE_TEMPLATE/`), scripts and hooks (`scripts/`), and the org docs and ADRs (`docs/`). It has no generated docs, so it keeps its own ADRs and cross-cutting changes in `docs/`, not `design/`. Its agent skills are in `.claude/skills/`.
- **`homebrew-tap`:** Homebrew formulas, updated directly by the bun-executable release workflow.
