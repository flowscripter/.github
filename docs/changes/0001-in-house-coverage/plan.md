# Plan: Replace Codecov with In-House Coverage Reporting

Refs flowscripter/.github#81. Spec: [spec.md](spec.md).

## Assumed Answers to the Spec's Open Questions

Nick approved the spec without answering its open questions. This plan uses the recommended answer to each one. Please confirm them on this PR, or say which to change:

1. Thresholds are inputs on the repo's caller workflow `.github/workflows/validate-*-pr.yml`: `coverage-total-min` (number), `coverage-patch-min` (number) and `coverage-gate` (boolean). The org default is the input default in the shared reusable workflow. A threshold change in a repo is a workflow-file change, so Nick pushes it.
2. Org default: 80% total, 80% patch. The repos measured below 80% get their own thresholds (see [Measured Coverage](#measured-coverage)).
3. The coverage badge is `coverage.svg`, generated by our own script and force-pushed as a single commit to an orphan `badges` branch with `PUSH_TO_MAIN_TOKEN`, served from `https://raw.githubusercontent.com/flowscripter/<repo>/badges/coverage.svg`. raw.githubusercontent.com serves `.svg` as `image/svg+xml` with `max-age=300` (checked 2026-11-28), so the badge can lag a release by up to five minutes.
4. Build uses GitHub's workflow badge. Version, docs and license are SVGs written to the same `badges` branch by the same step.
5. The coverage badge links to the release workflow's runs on `main`.
6. No new Rust coverage for `bun-rust-library`. Correction to the spec's premise: `check-bun-wasm-rust-source` already runs grcov and uploads both lcov files to Codecov today, so like-for-like means `bun-wasm-rust-library` reports the merged Bun and Rust lcov. `bun-rust-library` stays Bun-only.
7. Gate and badge on line coverage only (`LF`/`LH`/`DA` records). Branch and function records are ignored.

The plan also makes design decisions the spec left open. These are listed in [Decisions Made Here](#decisions-made-here) for the same confirmation.

## Findings From the Code

- **The Bun lcov file is in a different place.** `bun test --coverage --coverage-reporter=lcov > coverage.lcov` (in `check-bun-source`, `check-bun-rust-source` and `check-bun-wasm-rust-source`) captures the test runner's text output, not lcov. Bun writes the lcov to `coverage/lcov.info`. On 2026-11-28, every Bun repo that has tests produced `coverage/lcov.info`, and none of the redirected files contained an `LF:` record. Codecov's uploader found the real file by searching. The new step reads `coverage/lcov.info` and the redirects are dropped.
- **Repos with no `tests/` produce no lcov.** `check-bun-source` skips coverage when `hashFiles('tests/**')` is empty. `bun-ffi-loader`, `dynamic-cli-framework-api` and `example-plugin-api` have no tests on `main`, so Codecov never posts a status for them, which is the bun-ffi-loader#10 block. The new step treats "no lcov" as "no coverage data": it reports that in the summary and passes. The gate only applies when there is coverage data.
- **`repo-settings.py apply` keeps every existing required check.** `build_ruleset` starts from the existing contexts and only adds missing ones, so removing the codecov config alone would leave `codecov/patch` and `codecov/project` in every ruleset. The script has to drop them explicitly.
- **Removing the upload before the ruleset change blocks every PR.** Once nothing uploads, the required codecov contexts never report. So the ruleset change goes first (WP1), while Codecov still reports as a non-required status, and the upload is removed after it (WP2).
- **Callers can't pass inputs the reusable workflow doesn't declare yet.** A `with:` key that `workflow_call` doesn't declare fails the caller. So the inputs ship first with the gate off by default (WP2), the repos below the default set their thresholds (WP4-WP7), and the gate is turned on by default last (WP3). No repo goes red at any step.
- **Release `check` jobs and `release` jobs are separate jobs.** The `release` job holds `PUSH_TO_MAIN_TOKEN` and doesn't run tests. The coverage measured in `check` reaches the badge step as a job output, so no lcov file crosses jobs and no artifact action is needed.
- **The PR checkout is the merge commit.** In `pull_request` runs, `HEAD` is `refs/pull/N/merge` and `HEAD^1` is the base, the same diff the `changes` job already uses. Checking out with `fetch-depth: 2` gives the patch diff without fetching the base branch or using a token.

### WP2: `.github` - coverage step, report-only, and badges

- **Repo:** `flowscripter/.github`
- **Changes (agent-pushable):**
  - New `actions/coverage-report/` composite action with `coverage.py` (Python 3 stdlib, run with `python3 -I`). Inputs: `lcov` (space-separated paths), `total-min`, `patch-min`, `gate` (`true`/`false`), `mode` (`pr` or `push`). It:
    - sums `LF`/`LH` per `SF` over every lcov given, merging the `DA` lines of the same file (for the wasm type's two files);
    - in `pr` mode, reads `git diff --unified=0 --no-color HEAD^1 HEAD`, takes each added line, and counts it as coverable when its file and line have a `DA` record and as covered when the hit count is above 0. Paths are matched relative to the repo root, the way both Bun and grcov (`-s .`) write `SF`;
    - writes a Markdown table to `$GITHUB_STEP_SUMMARY`: total and patch, each as percentage and covered/coverable, the threshold, and pass, fail (with the shortfall in percentage points) or "not gated". Patch shows "n/a (no coverable lines changed)" when there are none, which passes. "No coverage data" when no lcov file exists or none has `LF` records, which passes;
    - sets the outputs `total` (percentage with one decimal, or empty) and `result`;
    - exits 1 only when `gate` is `true` and a threshold fails.
  - New `actions/publish-badges/` composite action with `badges.py` (stdlib). Inputs: `coverage`, `version`, `docs-url` (empty means no docs badge), `token`. It writes `version.svg`, `coverage.svg`, `license.svg` (from the SPDX `license` in `package.json` or `Cargo.toml`, otherwise `LICENSE`'s first line) and `docs.svg` into a temporary directory as flat two-part SVGs from one template. It runs `git init` there, commits as `github-actions[bot]`, and force-pushes to `refs/heads/badges` over HTTPS with the token, from a fresh orphan commit each time, so the branch never grows. Coverage colour: red below 60, yellow below 80, green at or above 80. With no coverage data the badge says `n/a`, in grey.
  - `actions/check-bun-source`, `check-bun-rust-source`, `check-bun-wasm-rust-source`, `check-rust-source`: remove the `codecov-token` input and the `codecov/codecov-action` step. Checkout with `fetch-depth: 2` and `persist-credentials: false`. Drop the `> coverage*.lcov` redirects. Add inputs `coverage-total-min`, `coverage-patch-min`, `coverage-gate`, and a final step that calls `coverage-report` with `lcov` = `coverage/lcov.info` (Bun types), `coverage.lcov` (rust), or `coverage.lcov coverage/lcov.info` (wasm), and `mode` = `pr` when `github.event_name == 'pull_request'`, otherwise `push`. Expose `coverage-total` as an action output.
- **Changes (Nick-pushed):**
  - `.github/workflows/validate-*-pr.yml` (all six): remove the `CODECOV_TOKEN` secret, add the inputs `coverage-total-min` (number, default 80), `coverage-patch-min` (number, default 80) and `coverage-gate` (boolean, default **false** in this package), and pass them to the check action.
  - `.github/workflows/release-*.yml` (all six): remove `CODECOV_TOKEN`, call the check action with `coverage-gate: false`, and expose its `coverage-total` as a `check` job output. Add a `badges` job: `needs: [release, check]`, `if: needs.release.outputs.tag != ''`, `permissions: contents: read`, steps `actions/checkout` (`persist-credentials: false`) then `flowscripter/.github/actions/publish-badges@v1` with `PUSH_TO_MAIN_TOKEN`, the tag, the coverage, and `docs-url` set in the four workflows that publish Pages (bun-library, bun-rust-library, bun-wasm-rust-library, bun-webapp). The job holds a secret, so it uses only `actions/checkout` and our own action (AC 12). In `release-bun-executable.yml` and `release-bun-rust-library.yml`, add it after the existing `release` job and leave the platform jobs alone.
  - `.github/workflows/test-scripts.yml`: run the two new test files.
- **Covers:** AC 1, AC 4, AC 8 (version, coverage, docs, license served from GitHub), AC 9, AC 10, AC 12, AC 5 (workflows and actions).
- **Commit type:** `feat`.
- **Tests:**
  - `actions/coverage-report/test_coverage.py`: lcov parsing (Bun and grcov samples, the merge of two files), the patch diff (added lines in covered, uncovered and non-coverable lines, renamed files, deleted-only diffs, files missing from lcov), the 80.0 boundary (at the threshold passes), gate off reports but passes, no lcov passes, the summary wording for each failure.
  - `actions/publish-badges/test_badges.py`: SVG output for each badge and colour band, valid XML, license detection.

## Decisions Made Here

To confirm along with the assumed answers above:

- A. Release runs report coverage but never gate (`coverage-gate: false` in every `release-*` workflow), so raising a threshold can't block a release of code that already passed its PR.
- B. "No coverage data" (no `tests/`, or no lcov) passes the gate and shows `n/a`, which keeps `bun-ffi-loader` and the API-only repos green with no special case.
- C. Rollout in three `.github` steps (ruleset first, report-only second, gate on last).
- D. `apply` makes the required checks exactly the canonical list, and `audit` treats extras as drift.
- E. The two low-coverage templates get tests to reach 80%, rather than a lowered threshold.

## Risks

- **Archived `mpeg-sdl-tool`** still has a Codecov badge in its README and can't be edited while archived. AC 5's check skips archived repos, as `repo-settings.py` already does.
- **AC 13 relies on the README being renamed when a repo is created.** The template READMEs name the template, and `repo-settings.py new` doesn't rewrite them (the `bun-ffi-loader` scaffold commit dropped the badges instead). A new repo's badges point at the template until its README is fixed. Open question 8 below.
- **Merged lcov for the wasm type:** grcov and Bun both write `SF` paths relative to the root, but if a path differs (`./src/...` and `src/...`), the merge counts the file twice. `coverage.py` normalises paths, and the test covers it.
- **CI numbers can differ from the local measurement** (Bun version, platform). WP3's check before it is marked ready catches that.
